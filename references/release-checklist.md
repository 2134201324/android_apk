# 交付清单

打勾之前不要发文件。每一条都对应过一次真实翻车。

---

## A. 包本身（5 分钟能全过）

```bash
bash scripts/verify.sh --apk dist/xxx.apk --expect-code 12
```

- [ ] `apksigner verify` 通过，输出里有 `v2 scheme` 或 `v3 scheme`
- [ ] 证书 SHA-256 与上个版本一致（不一致 = 换了钥匙 = 用户无法覆盖安装）
- [ ] `versionCode` 比上一版**大**（不是不等于，是大于）
- [ ] `versionName` 与交付说明一致
- [ ] 有 `launchable-activity`（否则桌面没图标）
- [ ] 有 `application-icon`（否则部分机型显示默认机器人）
- [ ] 不是 debuggable 包
- [ ] 体积合理：纯工具 <15MB，带 WebView 资源 <30MB，带原生库按 ABI 数量估算

---

## B. 功能（必须真机，模拟器不算）

- [ ] 冷启动 3 秒内出首屏，无白屏
- [ ] 首屏不需要登录/授权就能看到内容（一上来就弹权限是最差的体验）
- [ ] 主流程走通一遍：创建 → 编辑 → 保存 → 退出重进，数据还在
- [ ] 断网启动不崩；联网功能给出可读提示（不是"未知错误"）
- [ ] 深色模式下没有"白底白字"或"黑底黑字"
- [ ] 转屏不丢状态（表单内容、游戏进度、滚动位置）
- [ ] 返回键行为正确：页面内逐级返回，首页再按才退出
- [ ] 键盘弹出时输入框不被遮挡（`adjustResize` + `imePadding`）
- [ ] 长列表滚动不卡顿（100 条以上测）

---

## C. 升级（最容易被跳过，也最容易出事）

- [ ] 在**已装旧版**的设备上直接安装新版，能覆盖、数据保留
- [ ] 覆盖后打开，旧数据能正常读取（字段新增要给默认值，不能 `!!` 硬解）
- [ ] 卸载重装后，首次启动路径正常（不能依赖"升级时才存在"的文件）
- [ ] 如果改过包名 / 签名：**明确告知用户必须卸载重装、数据会丢**

---

## D. 交付物清单

一个目录，命名 `<应用名>-v<版本>-<日期>/`：

```
├── <应用名>-v1.2.0.apk          # 主产物
├── <应用名>-v1.2.0.apk.idsig    # v4 签名（增量安装用，可选）
├── 源码.zip                      # 完整可构建工程（含 gradlew）
├── signing/                      # 签名密钥（私有！单独加密或单独交付）
├── 交接说明.md                    # 本版本改了什么、怎么构建、已知问题
└── 验收记录.md                    # A/B/C 三张表的实际结果
```

- [ ] 源码 ZIP 解压后能直接 `./gradlew assembleRelease`（不含 `build/`、`.gradle/`、`local.properties` 的机器相关路径）
- [ ] ZIP 里没有 `signing/`（如果 APK 和源码要发给不同的人）
- [ ] 压缩包内文件数合理（几十个，不是几百个 —— 有几百个说明把历史版本或构建产物打进去了）

---

## E. 交付说明必须写清楚的四件事

1. **装不上怎么办**：先卸载旧版（数据会丢），或确认签名一致。
2. **权限要哪些、为什么**：逐项一句话，别让用户猜。
3. **数据存哪、怎么备份**：应用私有目录？导出功能？卸载即清空？
4. **已知问题**：诚实列出。藏着的问题会在用户手里变成"这软件有 bug"。

---

## F. 这些情况不要交付

| 情况 | 为什么 |
|---|---|
| 只在模拟器跑过 | 模拟器没有真实 SELinux、没有厂商 ROM 的后台限制、GPU 行为也不同 |
| `verify.sh` 有 FAIL | 每一项 FAIL 都对应一种"装不上/打不开" |
| 用 debug 签名发的 release 包 | 任何人拿到 debug key 都能给你的应用签一个"升级包" |
| 密钥丢了只留 APK | 下个版本无法覆盖升级，等于每次更新都要用户重装 |
| 没测过覆盖安装 | 这是用户更新时 100% 会走的路径 |
