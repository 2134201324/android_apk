# 交接模板

复制下面整段，把 `<>` 填掉。目标是**下一个 AI 不需要读历史对话就能继续干活**。

---

```markdown
# <应用名> 交接说明

## 一句话
<这个应用是干什么的、给谁用>。当前版本 v<版本>（versionCode <n>），包名 `<包名>`。

## 现在能不能构建
- [ ] 能：`cd <工程路径> && bash ~/.codebuddy/skills/android-apk-forge/scripts/build.sh --project .`
- [ ] 不能：卡在 <报错原文第一行>，已尝试 <做过什么>，怀疑 <方向>

## 关键路径
| 东西 | 位置 |
|---|---|
| 工程根目录 | `<绝对路径>` |
| 入口 | `app/src/main/java/<包路径>/MainActivity.kt` |
| 业务核心 | `<文件:行号>` |
| 签名密钥 | `signing/release.keystore`（口令在 `signing/keystore.properties`） |
| 证书 SHA-256 | `<指纹>` |
| 最近产物 | `<apk 绝对路径>` |

## 架构（三句话内说清）
1. <UI 层怎么组织>
2. <数据从哪来、存哪>
3. <有没有后台任务/服务/WebView>

## 技术选型与理由（只写会被质疑的那几个）
- <选型>：<为什么不选另一个>
- <选型>：<约束条件>

## 这一版改了什么
- <改动 1，一句话>
- <改动 2>

## 已知问题（按严重度）
1. **<P0/P1 问题>**：现象 <...>，根因 <...>，临时规避 <...>
2. **<问题>**：<...>

## 不要动的地方（动了会炸）
- `targetSdk` / `minSdk`：<理由，见 pitfalls 第 N 条>
- `<文件>`：<理由>
- `signing/`：换了钥匙用户无法覆盖安装

## 下一步建议
1. <最该做的事>
2. <其次>

## 环境
- JDK <版本>，SDK <路径>，build-tools <版本>
- 构建耗时：首次 <x> 分钟，增量 <y> 分钟
- 依赖缓存：<是否需要联网>
```

---

## 填写的三个原则

1. **写结论，不写过程**。"改成 targetSdk 28 是因为 W^X" 够了，不要写"我先试了 34 不行又试了 33"。
2. **路径写绝对路径**。接手者的当前目录一定和你不一一样。
3. **已知问题必须写**。你觉得"这个无所谓"的问题，在别人手里会花掉两小时。

---

## 如果交接给的是"另一个 AI"而不是人

额外补三条它一定会问的：

- **验收命令原文**：不要写"跑一下测试"，写 `bash scripts/verify.sh --apk dist/x.apk`。
- **当前分支/未提交改动**：`git status` 的输出贴一段。
- **上一次失败的命令**：能省掉它重走一遍弯路。
